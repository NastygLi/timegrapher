# Development

## Repo layout

```
firmware/pico_timegrapher/      Pico firmware: I2S + fixed-point detector (core 1), USB frames (core 0)
firmware/esp32_timegrapher/     ESP32 firmware: same detector, WiFi + WebSocket, serves the UI itself
  index_html.h                  generated by embed.py, do not edit
web/index.html                  UI: Web Serial (Pico), WebSocket (ESP32), or simulator
web/analysis.js                 JS detector, frame parser, BPH / rate / beat-error / amplitude, synthetic watch
test/analysis.test.js           end-to-end tests (Node, no dependencies)
embed.py                        inlines web/ into the ESP32 header
docs/                           documentation
```

## Tests

```sh
node test/analysis.test.js
```

The tests generate synthetic watch audio and check that rate, beat error,
amplitude and BPH are recovered across beat rates, noise levels, missed ticks
and clock error. They also check the serial frame parser with split chunks and
corrupt frames.

## Keeping the detectors in sync

The tick detector exists in three places:

| Where | Arithmetic |
|---|---|
| `loop1()` in `pico_timegrapher.ino` | Fixed point (RP2040 has no FPU) |
| `audioTask()` in `esp32_timegrapher.ino` | Float |
| `Detector` in `web/analysis.js` | Float; used by the simulator and tests |

They share the same structure and constants: a 4th-order Butterworth high-pass,
a `1 − 1/32 − 1/128` envelope decay, a `1/1024` down and `1/131072` up noise
floor, interpolated threshold crossing, and a 2 ms + 38 ms snapshot. If you
change one, change all three, so the tests keep describing the firmware.

## Serial protocol (Pico)

USB CDC serial; the baud rate is ignored. The host must assert DTR, which
Chrome's Web Serial does with `setSignals({ dataTerminalReady: true })`.

### Pico → host: framed binary

```
A5 5A | type u8 | len u16 LE | payload[len] | sum u8
```

`sum` is the low byte of the sum of the payload bytes. The receiver scans for
`A5 5A` and drops frames with a bad checksum, so it resynchronises after any
partial write.

**Type 1: tick** (all little endian)

| Offset | Type | Field |
|---|---|---|
| 0 | u8 | 1 (type) |
| 1 | u8 | 1 (version) |
| 2 | u16 | n, number of envelope samples (1920) |
| 4 | u32 | pre, samples before onset (96) |
| 8 | f64 | onset, sample index since boot, with fraction |
| 16 | f32 | peak envelope in window (full scale = 1) |
| 20 | f32 | noise floor at trigger |
| 24 | f32 | threshold at trigger |
| 28 | u16[n] | envelope, scaled so peak = 65535 |

**Type 2: stats** (JSON, every 500 ms)

```json
{"t":"stats","fs":48001.920077,"samples":5766656,"peak":0.012,"floor":0.0001,
 "thr":0.0006,"ch":0,"ticks":812,"dropped":0,"overruns":0,"board":"pico",
 "cfg":{"hpf":2000,"sens":6,"minThr":0.0002,"refractoryMs":75}}
```

`fs` is the exact I2S sample rate computed from the PIO divider. `overruns`
counts I2S buffer overflows; anything above 0 means samples were lost.

### Host → Pico: config lines

These are JSON objects terminated by a newline. All fields are optional:

```json
{"sens":6,"hpf":2000,"minThr":0.0002,"refractoryMs":75}
```

You can watch the stream with any serial tool, though the binary frames will
look like noise. Here is a minimal Python reader:

```python
import serial, json
p = serial.Serial('/dev/cu.usbmodem101'); p.dtr = True
buf = b''
while True:
    buf += p.read(p.in_waiting or 1)
    i = buf.find(b'\xa5\x5a')
    if i < 0 or len(buf) < i + 5: continue
    t, n = buf[i+2], buf[i+3] | buf[i+4] << 8
    if len(buf) < i + 6 + n: continue
    payload, buf = buf[i+5:i+5+n], buf[i+6+n:]
    if t == 2: print(json.loads(payload))
```

## ESP32 variant

The ESP32 sketch runs the same detector, but in float, and sends the same
tick payload (without the `A5 5A` framing) as WebSocket binary messages. Stats
go out as WebSocket text. The page is compiled into the firmware, so a phone
can connect directly.

- Wiring: SCK→GPIO32, WS→GPIO25, SD→GPIO33, L/R→GND, VDD→3V3.
- WiFi: by default it starts an access point **Timegrapher** (password
  `timegrapher`) and serves the UI at <http://192.168.4.1/>. To join an existing
  network instead, set `STA_SSID` / `STA_PASS`.
- After changing anything in `web/`, regenerate the header:

```sh
./embed.py
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/esp32_timegrapher
arduino-cli upload  --fqbn esp32:esp32:esp32 -p /dev/cu.usbserial-XXXX firmware/esp32_timegrapher
```

The page picks its data source automatically:
- **WebSocket:** when it's served over HTTP by a device.
- **Web Serial:** when it's opened as a local file and you click Connect.
- **Simulator:** when there's no device, or with `?sim`.

The ESP32 build compiles but hasn't yet been tested on hardware.
